# Explorer breakage log

Each time Safe C gets in the way of the explorer, it gets one row here: a rule fight,
a missing module, a slow path, or a workaround. This log and the app are the two
things the explorer produces (plan R13, KTD13). The wiki page
`research-wiki/concepts/safe-c-application-stress-test.md` summarises it.

Columns:

- **When:** the date and milestone.
- **Rule, module or tool:** what got in the way.
- **What happened and its cost:** what broke and what the workaround cost.
- **Resolution:** a stdlib fix, an adapter, an app workaround, a proposed subset
  change, or `open`.
- **PR:** where it was resolved.

A subset change needs a row here and Robert's approval first (plan R10).

## Seeded from planning

These ten gaps came out of reading the stdlib and the subset before any explorer code
existed (U1). Each one started `open`, with a "planned" note for what the plan
expects; the PR that resolves a row replaces the note with what actually happened.

| 2026-10-26 M1 | `handle`, `chan`, `mailbox` | A channel or mailbox message is a handle. Sending one `size_t`, such as a request id, means allocating a handle in the sender's table first. Every message costs an alloc and a free. | App workaround as planned: the message is a pool arena index with a header in the arena (SC-37), and `examples/explorer/wire.c` hides the take, send, receive and free in four calls of about 50 lines; nothing holds a handle between messages. | SC-38 |
| 2026-10-26 M1 | `handle` | Each slot retires after 65,535 reuses, and there is no API to renew a table. A long session runs out. | App workaround as planned: since no handle is held between messages, `wire.c` resets the table's own arena and builds a new table when an alloc fails or a receive reports NOSLOT. The ring arenas are separate and never reset. `tests/explorer_wire_test.c` runs three times 65,535 round trips through one-slot tables, and a NOSLOT receive. | SC-38 |
| 2026-10-26 M2 | stdlib | There is no MPMC queue and no shared free list, and `chan` has one reader. | 2026-10-26 M2 | stdlib | Outside `chan` and `mailbox`, the stdlib has no atomic flag, so a cancel or wake flag has no subset-clean form. | Adapter: `sc_flag` in `adapters/thread.c`, an `atomic_bool` whose set reports whether this call moved it. | SC-35 |

| 2026-10-26 M1 | `make lint` | Lint scans every `.c` and `.h` under `examples/`, so the Clay header cannot be vendored next to the app. Clay's macros fail the subset. | Adapter: Clay lives in `adapters/third_party/`, compiled from `adapters/ui.c`. | 2026-10-26 M3 | `tslice` | `sc_tslice_get` and `sc_tslice_set` copy an element in or out. There is no pointer to an element, so changing one field of a record means copying the whole record twice. | 2026-10-26 M1 | R1-no-subscript, R3-no-char-ptr | `int main(int argc, char **argv)` and any `argv[i]` read break the subset, so application code has no subset-clean way to receive argv. | Adapter: `adapters/ui.c` owns `main` and passes the arguments as a `sc_tslice` of `sc_str` to `app_main` (KTD17). | SC-33 |

## Milestone 3 retrospective (U9 to U12)

SC-40 (#74), SC-41 (#75), SC-42 (#76) and SC-43. Milestone 3 turned one query into
something to browse: UTF-8 input and output, a result model that finds any row of a
streamed set, a virtualised grid with a detail pane, and tabs that share the
connection, close mid-stream and load a million rows.

**Fixed in Safe C:** the missing UTF-8 module, seeded in milestone 2's log, became
the proved `utf8` stdlib module (SC-40: 388 goals proved, 2 waived, 89 of 91
mutants killed and 2 equivalent). Two adapter additions are small: `ui_log`, and
`sc_clock_us` in the thread adapter.

**Worked around in the app:** no reader that can seek (64 row marks per chunk);
no width tables (wrapping measures each prefix through the adapter); no pointer to
a tslice element (tabs and results move by value); a custom node learns nothing of
its laid-out rectangle (hit testing repeats the layout by hand). All of these were
cheap in time. The workarounds cost readability and one convention nothing checks
(only one copy of a result is filled at a time).

**Open:** no italic, emoji or CJK glyphs; the 128-column grid cap; the hand-kept
hit origin; a custom node's background covering its draws.

**Bugs the gates found:** review found a frame arena the detail pane could fill
silently, inverted horizontal scrolling, a double ellipsis and a 64-action step
limit that broke the link on a rerun. The stdlib caught none of them by type. The
frame-arena case failed soft because `text_new` turns an allocation failure into
an empty string; that is still the case.

**Did KTD2's thin-adapter bet hold?** Yes. Lines of C at the end of each milestone:

Through milestone 3 the app grew by 2,297 lines. The UI adapter grew by 50: wheel
position, Page Up/Down, the font fallback and `ui_log`. The libpq adapter did not
change. Everything else the grid, tabs and result model needed was written as
subset application code. Of the explorer's 6,973 lines at b56c5df, 3,827 (55%) are in
modules with unit tests: the core `conn`, `proto`, `result`, `grid`, `detail`, `tabs`,
`input` and `query_text` (3,370), plus `frame`, `theme` and `wire` (457). The tab

rows; software rendering dominates.
